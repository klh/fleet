# W1124.18.1 — Plan: self-healing supervisor and governor against measured progress

ADR for Phase 1 of the owner sequence in W1124.18: prove sustained40 first
(milestone gate, owner law), then a self-healing supervisor/governor, then
hub-hosted execution (W1124.18.2) and offline continuity (W1124.18.3).
Planning only — no controller code lands from this item. Implementation is
gated behind the sustained40 milestone and a reviewed plan (this document is
the plan; review rides the existing `decision work.review` receipt plane).

## 1. Inventory — what runs today (facts, verified 2026-10-23)

All controllers already live in ONE heartbeat process (`hooks/bin/fleet-loop.ts`),
not in scattered daemons. Per cycle (~120 s):

| Concern                      | Surface (packages/suspenders)                                        | Ownership guard today                                                              |
| ---------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Dispatch                     | `hooks/lib/fleet-loop/dispatch.ts` (`runDispatch`)                    | DB launch lease `acquireLaunchLease` + durable `lane_launch_intents` + claim token |
| Launch backoff / budget      | `scripts/lib/launch-backoff.ts`, `scripts/lib/lane-retry-budget.ts`   | `laneAttemptLimit` (SUSPENDERS_LANE_MAX_ATTEMPTS), park + eligibleAt                |
| Maintenance heartbeat        | `hooks/lib/fleet-loop/maintenance.ts` (`MAINTENANCE_TASKS`)           | attempt-stamps (`~/.claude-insights/maintenance-stamps.json`), nice, timeoutMs     |
| Stall / dead-claim           | `hooks/lib/fleet-loop/stall-watch.ts`                                 | per-episode events (stall.json/dead-recovery.json 0600), CAS reclaim, receipt match |
| Recovery budget              | `hooks/lib/dead-claim-recovery.ts` (`reserveRecovery`, cap 3)         | `work_recovery_attempts` table, atomic reservation, operator reset verb            |
| Recovery policy (fail-closed)| `hooks/lib/automatic-recovery.ts` (`automaticRecoveryCheck`)          | paused flag, PAUSED/WAIT_RATE + open decisions hold, probe + intent dead-check     |

Installed faces: launchd `com.suspenders.*` (one loop instance per machine),
shims `work`/`coord`/`dispatch`, board :7799, store :7794/:7795/:7796.

Gap analysis against the mission verbs:

- **Per-project controller ownership is implicit.** The loop is a per-machine
  singleton by launchd convention; dispatch has a DB lease, but loop-level
  controllers key their state machine-locally (maintenance stamps in `$HOME`,
  stall state in `<repo>/.fleet/`). A second loop on another machine would
  double-fire maintenance and race the merge ladder (git-state mutex only).
- **Progress is activity-inferred, not attribution-based.** stall-watch reads
  file mtimes + transcript freshness. A lane running a 20-minute suite looks
  stalled; a lane spinning on failed inference looks productive. No live join
  of W776 attribution (inference/tool/artifact/commit) against the claim.
- **No incident lifecycle.** NEED_DECISION rows and lane.* events exist, but
  nothing states open→ack→mitigating→resolved→banked-lesson, with escalation
  timers, in one place.
- **Capacity is open-loop.** quota-sweep, metrics-alert and `work allocate
  --capacity` exist, but throttle/quota verdicts never feed back into
  allocation or dispatch pacing as one signal.

## 2. Requirements → design

Mission verbs mapped to one mechanism each. Reuse law: the plan adds **zero
new daemons and zero new transports**; every mechanism lands in the existing
fleet-loop task registry, the store, or an existing CLI verb.

### R1 — Per-project controller ownership contract (the lease)

One durable row per (project, controller-class) in governor.db
(`control_leases` table, minted by a store migration): columns
`project, controller, epoch, owner_host, owner_pid, expires_at, nonce`.
Semantics:

- Acquire = transactional `INSERT OR ... WHERE expires_at < now` CAS; heartbeat
  renews `expires_at = now + ttl` every cycle. Expired lease = free to take,
  epoch increments (W1124.18.3's fencing token, minted here once).
- Controller classes: `dispatch`, `merge`, `maintenance`, `watchdog`,
  `recovery`. The loop takes ALL classes by default (today's behavior,
  formalized); a hub-hosted loop (W1124.18.2) takes a subset — e.g. hub takes
  `merge`+`maintenance`, Mac keeps `dispatch`. Splitting ownership = two loop
  invocations with `--controllers <set>`; never two owners of one class.
- Non-owners observe-only: they still read lanes/events (liveness, board) but
  never mutate claims, never fire maintenance tasks, never merge. A losing
  loop logs `CONTROL YIELD <class> <winner-host/epoch>` once per epoch change.
- Ratchet: a class is acquired only by a loop whose installed generation
  matches the fleet version pin; a version-mismatched contender yields.
  (Version pin already exists — `~/.config/klh/stack.yaml version:`.)
- Repair path: `fleet-loop --release <class>` writes a release + epoch bump;
  a crashed owner's lease lapses naturally (ttl 3× tick) — no operator rm of
  state files, no destructive reclaim of the lease itself.

### R2 — Observed progress join (semantic stall verdict)

One fleet-loop task `progress-join` (advisory, default cadence 300 s):
joins, per RUNNING/CLAIMED lane, three existing feeds — no new instrumentation:

1. **Inference**: W776 attribution rows (router_usage ledger, already written
   by the belt router) for the lane's window.
2. **Tool/artifact**: `.worktrees/<item>` product-path mtimes (the
   newestFileMtime walk stall-watch already does) restricted to product paths.
3. **Commit**: `git -C <wt> rev-parse` vs the lane's baseline sha (the
   claim-time HEAD), plus done-capsule checkpoints.

Verdict function (pure, testable, clock-injected — reuse the maintenance
override idiom): `progress(lane) → productive | stalled | long-idle`:

- `productive`: any feed advanced since last check.
- `stalled`: no feed advanced for ≥ stall-after (default 25 min, today's
  STALL_WARN_MS default) AND the lane's session state is not PAUSED/WAIT_RATE
  and has no OPEN decision (same holds automaticRecoveryCheck already honors).
  Emit `lane.stalled` once per episode (existing event; add `feeds` payload
  naming which feeds are flat).
- `long-idle`: `stalled` and age ≥ long-after (default 90 min) → escalate to
  NEED_DECISION instead of a second stall event.
- Legitimately-long carve-out: a lane whose last inference row is fresh
  (< 10 min) but whose artifacts are flat is `productive` — that is a suite
  running, not a stall. Inference freshness is the semantic discriminator the
  mtime walk lacks; it comes for free from the attribution ledger.

This **replaces** the mtime-only verdict in stall-watch (the file walk stays
as feed #2); stall-watch's episode/recovery machinery is unchanged.

### R3 — Bounded recovery state machine

Formalizes today's implicit machine (already coded in dead-claim-recovery +
stall-watch + reclaim-all) into one named FSM, one implementation:

```
live → (identity absent) → grace(10m) → quarantined
quarantined → recoveryAttempt (reserveRecovery, cap 3, atomic, consumed on failure)
           → released (receipt match + READY re-read)  → claim READY, capsule preserved
           → held (receipt mismatch / still not READY) → decision(NEED_DECISION)
exhausted  → decision(NEED_DECISION)                   [re-entry: dead-claim-recovery reset]
```

Codify: recovery never destroys work — released claims keep the worktree,
branch, capsule, per-lane buckle key (revoked only on done/test-key rule),
and the W846 tag lineage. Reclaim receipts stay the only accepted proof of
release (reclaimReceiptMatches). This FSM statement is the spec the existing
tests already pin; the plan's only code change is a shared module both
stall-watch and reclaim-all import, so the rules are DRY.

### R3b — Incident lifecycle and escalation

One store-backed lifecycle over the existing `decisions` + `events` tables:

- **Incident row** minted by the FIRST controller that observes a terminal
  condition (recovery exhausted, merge-ladder repeated conflict, controller
  class contested > 2 epochs, sustained provider throttle). Payload carries
  the evidence bundle (episode JSON, receipts, log paths) — machine-local
  paths only after scrub rules.
- States: `open → acked → mitigated → resolved | open→superseded`; transitions
  via coord verbs (`incident ack/resolve`), every transition an event row.
- Escalation: `open` past 2× the class's cadence → board NEED_DECISION
  render + W822 pulse inclusion; past 24 h → chatgpt-coordinate trigger class
  (the W1013 scan already fires on `item failed after >=2 runs`; incidents
  join that trigger list).
- Postmortem: `resolved` requires a `lesson.*` fact (coord fact set) or an
  explicit `no-lesson` note in the resolve — the silent-resolution escape
  closes.

### R4 — Capacity feedback and retry budgets (one signal)

- Retry budgets: `lane-retry-budget.ts` is the ONE budget source for launches;
  `work_recovery_attempts` is the ONE budget for ownership recovery. New rule:
  recovery and launch budgets are **independent** (a launch-exhausted item can
  still be recovered; a recovered claim restarts its launch budget cleanly —
  today's park/eligibleAt already does this; codify, don't change).
- Capacity signal: quota-sweep and metrics-alert already emit events; the plan
  adds **no new collector** — `work allocate` gains a read-only
  `--respect-capacity-events` input (default on) that down-weights READY
  planning for items whose lane class is under an active throttle/pause event,
  and dispatch defers (not refuses) when the item's carrier group is
  throttled. Bounded: a throttle event carries its own expiry; stale events
  never gate.

### R5 — Proof-based completion + independently reviewed ancestry

Already law; the plan does not relax any of it. Restating as contract:

- `work done` gates: capsule checkpoint == completion sha, test-name diff vs
  branch baseline, W511 marker scan on added lines, patch-first near-cap, and
  the work.done event with attribution (W776) banked.
- Published ancestry: the merge ladder merges only branches whose item closed
  with `verified=true` (git-ancestor verification); independent review rides
  the `decision work.review` receipt plane (verdict + blocking findings +
  reviewer identity in the receipt JSON — see W1087.1's receipt, 2026-10-23).
- Sustained40 definition (feeds the milestone gate): N≥40 lanes over a
  rolling 24 h where each lane has (a) attribution rows, (b) ≥1 commit in
  ancestry of main, (c) a work.done with verified=true and a review receipt,
  (d) zero incidents of double-execution. Composed from existing ledgers
  (router_usage, events, decisions) — one read-only report verb, no new
  tracker.

### R6 — Health/trace/events/test-clock reuse

- Health: verdicts stay outside-process (probe sidecars; health-status-contract).
  Controller liveness joins the same contract: the loop gains no /health of
  its own — its verdict comes from the maintenance-stamp freshness + the
  board's store session rows (an already-observed surface).
- Events: `emitLoopEvent` / coord emit are the only broadcast channels.
- Test clocks: `createMaintenanceSweep` already injects `now`/`spawn`/`stampsPath`;
  every new mechanism above takes the same injected-clock shape (R2's verdict
  function, R1's lease expiry, R3b's escalation timers) — tests never sleep.

### R7 — What this plan explicitly rejects

- **No second supervisor daemon.** Everything lands in the ONE fleet-loop
  registry (a new MAINTENANCE_TASKS row or a cycle step), or an existing CLI
  verb. A controller that cannot be expressed as a loop task is a design smell.
- **No destructive reclaim.** reclaimAll's unknown-never-releases and
  3-dead-pass rules are invariants; recovery (R3) cannot bypass them. The
  `.fleet/reclaim-paused` and `.fleet/rogue-reap-paused` flags remain the only
  pause channels.
- **No duplicate controllers.** R1's lease makes double-fire structurally
  impossible per class; the launch lease and merge git-state mutex stay as the
  operation-level second belt.
- **No LLM-judged liveness.** Progress verdicts are ledger joins (R2), not
  model opinions; signals-scan (post-close) stays the only LLM analysis.

Each row: injection → expected behavior → proof artifact. "Drill" = the
executable drill (a `bun test` fixture that injects the fault via the
existing seam — injected spawn/clock, or a sandboxed store in /tmp).

| - | ------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| 1 | Missing subscriber       | kill coord subscribe WS before an event             | Event rows persist in store; lane loses only the push, not delivery truth; catch-up `coord inbox` delivers                | events row exists; inbox shows it      |
| 2 | Stuck RESUME_READY       | READY item with dead intent + registry row          | reclaim/launch never trusts registry alone; intent dead-check + claim CAS gate dispatch                                   | drill: no duplicate lane; item dispatchable |

## 4. Decomposition and dependency-ordered acceptance

Reusable packages/interfaces (all in packages/suspenders, no new package):

- `hooks/lib/control-lease.ts` — R1 lease (table + acquire/renew/yield).
- `hooks/lib/progress-join.ts` — R2 verdict function (pure, clock-injected).
- `hooks/lib/incident-lifecycle.ts` — R3b states + escalation timers.
- fleet-loop: new `progress-join` task; existing tasks take the lease before
  mutating; stall-watch/reclaim-all import the shared R3 FSM module.
- `work allocate --respect-capacity-events` (R4) + a `work incident` verb
  face for R3b transitions (coord verbs over the store, verb-kit law).

Dependency order (each step proves itself with the named drill before the
next):

1. control-lease + the 10-fault drill harness scaffold (faults 3/4/10 need it).
2. progress-join verdict + stall-watch swap (faults 1/2/6 prove liveness truth).
3. shared R3 FSM module extraction (faults 7/8 prove non-destructive recovery).
4. incident lifecycle + escalation (faults 5/9 prove escalation paths).
5. sustained40 report verb (milestone measurement, read-only).
6. Only after sustained40 passes: hub-side controller classes (W1124.18.2's
   scope) — this plan's lease contract is the prerequisite.

Acceptance for THIS item is the reviewed plan itself; implementation items get
minted from §4 only after review and only after the sustained40 gate opens.

## 5. Alternatives considered

- **A dedicated supervisor daemon** (separate process/launchd unit): rejected —
  violates the W779 one-heartbeat law and adds a second ownership surface;
  the fault matrix's controller-restart row doubles in size.
- **Controller ownership by machine-local lockfile**: rejected — lost store /
  restart faults (3/4) desync it from the store; the store is the one truth
  (centralized-ledger law).
- **LLM-judged progress ("ask a model if the lane is stuck")**: rejected —
  non-deterministic, unbounded cost per cycle, and the attribution ledger
  already answers it deterministically.
- **Reactive-only (no lease), rely on today's per-operation guards**: viable
  for one machine, but W1124.18's hub phase requires a second machine to hold
  `merge`+`maintenance` while `dispatch` stays local — without R1 that is
  exactly the duplicate-controller fault; rejected as the end-state, kept as
  today's transitional reality until §4 step 6.
