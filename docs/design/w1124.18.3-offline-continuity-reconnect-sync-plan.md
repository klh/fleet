# W1124.18.3 — Plan: offline continuity and idempotent reconnect synchronization

Phase 3 of the owner sequence in W1124.18. Phases 1–2 (W1124.18.1/.2) prove
sustained40 + the self-healing supervisor, then capability-advertised hub
execution whose §5 step 7 lands the store artifact surface this plan
consumes. 18.2's R4 step 8 hands over the invariant this plan specifies:
"the dev machine rejoins as a client; its pending state is read-only replay
against the authoritative graph (idempotent by event id and CAS tokens)."
Planning only — no controller code lands from this item. Implementation is
gated behind the sustained40 milestone and a reviewed plan (this document is
the plan; review rides the existing `decision work.review` receipt plane).

Gap analysis against the mission verbs:

- **The outbox is consult-scoped.** `consult_outbox` proves the durable
  delivery pattern but carries only consults; a partitioned lane's closure,
  notes, receipts and decision proposals have no durable local intent row,
  so they are lost on crash or must block on the store (fail-closed), and a
  lane that finishes while partitioned has nowhere to park its closure.
- **No bounded event replay face.** `readEvents` is in-process; over the
  network the only event face is the WS push (delivery, not durability). A
  reconnecting client cannot keyset-pull `id > cursor` across the wire.
- **No artifact/commit manifest.** Proof lives in done events + git; there
  is no bounded manifest a reconnecting UI can list to reconcile "what
  finalized, on which branch, at which sha, with which review receipt".
- **No retention bounds on the stream.** The events table grows unbounded;
  without a retention horizon a cursor can always fall behind forever, which
  is the unbounded-replay bug the mission forbids.
- **No store-loss detection on reconnect.** instanceId pinning exists but is
  consult-internal; a re-seeded store after loss silently invalidates every
  cursor with no loud signal to the owner.

## 2. Requirements → design

Mission verbs mapped to one mechanism each. Reuse law (inherited): zero new
daemons, zero new transports — every mechanism lands in an existing lib, the
fleet-loop task registry, an existing verb, or an existing HTTP face family
(the store-server route table). The authority model is 18.2's decision A:
ONE authoritative writer per project (adjudication.c71-73), movable by lease
handoff, every mutation epoch-fenced; partitioned parties degrade to
read-only last-known.

### R1 — the reconnect session (one lib, one task, one trigger)

`hooks/lib/reconnect-sync.ts`: pure, clock/fetch/db-injected, driven by ONE
fleet-loop maintenance task (`reconnect-sync`, attempt-stamped, nice,
timeoutMs, honors a `.fleet/reconnect-paused` flag) plus one trigger at `coord
subscribe` (re)attach success. One session, bounded:

1. **Read the sync manifest** — `GET /sync/manifest` on the authority:
   `{sync_version, instanceId, generation, log_horizon, retention_days,
   server_ts, counts}` — bounded JSON (16 KB cap, readJson idiom). An
   unknown `sync_version` = read what you can, mutate nothing.
2. **Identity gate**: `instanceId` matches the pinned identity → cursors
   valid; changed → **snapshot recovery**: invalidate cursors, full current-
   state read (work list, sessions, decisions, lanes), emit NEED_DECISION
   (store rebuilt — verify no loss), never replay stale deltas against a
   store that lost them.
3. **Drain the outbox** (client → authority, R2) — `POST /sync/drain`, oldest
   first, per-intent isolation: one intent's failure retries alone; drain
   re-checks item state + claim token (CAS) before applying; outcomes DRAINED
   / STANDDOWN (stale epoch, closed elsewhere) / EXPIRED (TTL).
4. **Replay the inbox** (authority → client) — `GET /sync/events?since=
   <cursor>&limit=<n>` keyset pages; a cursor behind `log_horizon` = the gap
   is unReplayable → snapshot recovery instead of a partial replay (bounded
   replay law). Cursor advances to the last EXAMINED row (W644 law).
5. **Reconcile lanes**: local lanes whose canonical claim moved (reclaimed,
   re-dispatched, closed elsewhere) stand down locally: release the
   worktree claim cover, emit one standdown event, keep the commits on the
   branch. The board banner flips from "degraded: last-known (stale Ns)" to
   live only after steps 1–4 complete.

### R2 — the durable outbox (`reconnect_outbox`)

One table (client-side store migration), one row per deferred mutation,
minted transactionally WITH the local action it records:

```sql
CREATE TABLE IF NOT EXISTS reconnect_outbox (
  delivery_id TEXT PRIMARY KEY,   -- crypto.randomUUID(), minted with the row
  kind TEXT NOT NULL,             -- 'done' | 'note' | 'ack' | 'decision'
  item TEXT,                      -- work item id when scoped to one
  payload TEXT NOT NULL,          -- versioned JSON (typed schemas below)
  status TEXT NOT NULL DEFAULT 'PENDING',
  attempts INTEGER NOT NULL DEFAULT 0,
  next_at INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  remote_store_id TEXT,           -- pinned at first successful handshake
  last_error TEXT                 -- bounded codes only, never raw exceptions
);
```

Intent kinds and their payload schemas (exact keys, extra/missing = malformed
— the consult-relay idiom):

- **`done`** — a lane finished while partitioned: `{sync_v: 1, item, sha,
  branch, base_sha, capsule_note, claim_token, epoch, generation}`. Drain
  runs the FULL done-gate against the authority (claim-check W833, tokens,
  marker scan, patch-first) — the gates run at DRAIN time, so an offline
  lane never bypasses proof; a stale token or closed item = STANDDOWN, the
  commits stay on the branch, no double execution. **done intents never
  TTL-expire** — only CAS can stand them down; the work product is on git.
- **`note`** — `coord message`/`NEED_DECISION` composed while partitioned:
  `{sync_v: 1, target_sid, kind, note, created_at}`. TTL 7 days (the
  consult_outbox law): a stale interrupt is noise, EXPIRED honestly.
  NEED_DECISION notes ride this kind, not `decision`.
- **`ack`** — a directed event processed while partitioned: `{sync_v: 1,
  event_id, event_ts, state: 'ACCEPTED'}`. Honors W957 verbatim: receipts
  drain only for events actually processed; never backfills; the receiver
  upserts `direct_message_receipts` idempotently by (event_id, sid).
- **`decision`** — a decision proposal composed offline:
  `{sync_v: 1, decision_id, proposal, created_at}`. The authority inserts
  transactionally with a same-id CAS: a second proposal for a live decision
  id rejects with a `decision.conflict` event (board-visible). Conflicting
  decisions are never auto-merged — a human closes them.

Drain semantics: `status` PENDING → DRAINED | STANDDOWN | EXPIRED; `note`,
`ack`, `decision` intents get the consult_outbox 7-day terminal-row sweep;
terminal-row sweep skips `done` rows (never delete un-drained closures).
Retry: capped exponential backoff (60 s cap, consult_outbox idiom), bounded
codes in last_error (network payloads never persisted).

### R3 — bounded replay, retention, and the rows-are-truth law

The events table is the sync stream, not the truth. Truth = the rows the
events describe (work_items, claims, sessions, decisions, knowledge,
artifacts). One fleet-loop maintenance task (`event-retention`) prunes the
stream: `DELETE FROM events WHERE ts < now - retention_days` (propose 30
days), bounded per cycle (LIMIT), attempt-stamped, honoring
`.fleet/reconnect-paused`. Consequences:

- **Replay bounds**: a client cursor always sits above or below the horizon.
  Above: keyset pages until caught up. Below (gap): snapshot recovery —
  read current rows, reset the cursor to the log head, never replay a gap
  that could silently skip events. The manifest publishes `log_horizon`
  (oldest retained id) so the client decides deterministically.
- **Rows are truth, events are the stream**: pruning never loses durable
  state; the board and the done-gate read rows, not the stream. This is
  what makes retention safe under the no-data-loss acceptance.
- **No data loss**: commits live on git (branch push survives everything);
  capsules ride the store rows; the outbox is durable client-side; the only
  pruned surface is the replayable stream whose gaps trigger snapshots.

### R4 — artifact/commit manifests

Consumes 18.2 §5 step 7's bounded blob surface. One authority-side table:

```sql
CREATE TABLE IF NOT EXISTS artifacts (
  id TEXT PRIMARY KEY,            -- content-addressed sha256
  item TEXT,                      -- owning work item, nullable
  kind TEXT NOT NULL,             -- 'drill-receipt' | 'log' | 'trace' | 'blob'
  bytes INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  retention_until INTEGER NOT NULL,
  state TEXT NOT NULL DEFAULT 'present' -- present | unavailable | reaped
  -- + bounded: per-artifact cap, per-item count cap, retention sweep
);
```

- **Commit manifest**: NOT a new table — the done events + merge events
  already carry {item, sha, branch, base via merge-base} and review
  receipts. The reconnect session verifies exact reviewed ancestry: fetch
  the branch, assert `done sha` is reachable, capsule checkpoint == done
  sha (existing law), merge receipt present (verified-only merge ladder).
  Any gap = a board-visible ancestry gap, never silently papered over.
- **Artifact manifest**: `GET /sync/artifacts?since=<cursor>&limit=<n>` —
  bounded keyset listing of the artifacts table. Missing artifact (fetch
  404 or reaped row): mark UNAVAILABLE locally, board-visible, re-derive
  from git proof where possible (drill receipts are committed proof), never
  block the sync session, never fabricate.
- **Trace receipts**: cross-hub trace pulls ride telemetry's
  `remote-traces.ts` shapes verbatim (bounded peer connector, 256 KB cap,
  honest status enums) — no second trace transport.

### R5 — epochs, ordering, deduplication, acknowledgments

- **Epochs**: 18.2 R3's law verbatim — claim token = epoch + claim nonce;
  every drained intent carries it; the authority CAS-rejects superseded
  epochs. A standdown is an event + status, never a crash.
- **Ordering**: total order = per-store AUTOINCREMENT id; keyset replay
  preserves it; cross-store (relayed) events carry origin ts + delivery ts.
  Outbox drains oldest-first, order deterministic
  (created_at, delivery_id), and drain (R1 step 3) precedes reconciliation
  (R1 step 5): a done-intent always gets its gate-checked drain before
  reconciliation stands down the local lane, so finished work is never
  orphaned by its own drain order.
  Out-of-order delivery cannot scramble state: each intent is CAS-gated on
  current canonical state, not on arrival order.
- **Deduplication**: receiver-side dedupe = the intent's CAS on canonical
  state + the status flip transaction (crash between POST and status flip
  = a retry that CAS-rejects idempotently — "already closed" reads as
  DRAINED). No delivery-table needed on the receiver: the work graph's own
  state machine is the dedupe surface. For `note`/`ack` kinds the receiver
  keeps the existing receipt/insert dedupe (W1061, W957 laws).
- **Acknowledgments**: `ack` intents (R2) close the loop for directed
  events processed offline; consult answers keep consult_outbox's own ack
  law; drain outcomes are the ack for intents (the client reads the 200 +
  status flip; a lost response retries and CAS-rejects idempotently).
- **Credential scoping**: lanes keep per-lane `bksk_` keys (revocable,
  audited); the sync session rides the client's store binding
  (`x-governor-token`, consult_outbox idiom) — never a lane key; git pushes
  stay per-hub deploy keys with the scrub gate. A revoked store token = the
  drain retries with capped backoff, honest failure, no partial drain.

### R6 — never replay completed execution, never double-merge

- A drained done-intent re-runs the full done-gate at drain time: if the
  item closed elsewhere while partitioned, the claim token CAS-rejects →
  STANDDOWN. No replay of completed execution, structurally.
- Merges are authority-only (18.2 R3: partitioned parties cannot merge).
  There IS no client merge intent, so client reconnect cannot double-merge;
  authority-side, the merge ladder's MERGE_HEAD mutex + mergeRunnerAlive +
  verified-ancestry requirement + review receipt make double-merge
  structurally impossible (a second merge of the same ancestry has no
  verified-new state to merge and no ladder hold).

## 3. Failure model — the acceptance fault matrix

Each row: injection → required behavior → proof drill. Drills become bun
test fixtures against a sandbox store (temp project, temp store, injected
clock/fetch/spawn — the maintenance override idiom). Acceptance = ALL rows
green + the three global assertions: eventual progress visibility (board
rows == authority rows after convergence), exact reviewed Git ancestry
(done sha reachable, capsule == sha, review receipt present), no data loss
(every lane commit reachable or preserved on its branch).

| #   | Fault                        | Injected by…                                        | Required behavior                                                                                                            | Proof drill (test fixture)                                        |
| --- | ---------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1   | Dev poweroff, 40 lanes riding | Stop the client loop + lanes mid-run                | Hub keeps cycling (18.2 R4); on reconnect cursor replays the window; done-intents drain through full gates; commits preserved | hub closes items, client reconnect drains, zero double-done       |
| 2   | Hub/store restart            | Kill store-server mid-window, restart               | Same instanceId → cursors valid, sync resumes exactly; re-seeded (new instanceId) → snapshot recovery + NEED_DECISION         | no stale replay; identity change is loud                          |
| 3   | Partition / rejoin           | Firewall client mid-lane                            | Last-known read-only; local lane finishes on own claim; done-intent pends; rejoin drains through gates; stale = STANDDOWN      | zero mutations while partitioned; drain gated at rejoin           |
| 4   | Duplicate delivery           | Replay the drain POST twice                         | Receiver CAS + status flip = idempotent; one done event total                                                                | one lane, one claim, one done                                     |
| 5   | Out-of-order delivery        | Reverse intent creation order at drain              | Drain order deterministic (created_at, delivery_id); per-intent CAS on canonical state ignores arrival order                  | final state identical to in-order drain                           |
| 6   | Stale leader / decision conflict | Two proposals for one live decision id          | One inserts, other rejects + `decision.conflict` event, board-visible; no auto-merge                                          | one decision row, one conflict event                              |
| 7   | Credential revocation        | Revoke a lane `bksk_` key mid-run; revoke store token | Lane pauses (governance), no partial publication; drain retries honest, no partial drain                                   | paused lane, no artifacts leaked, drain state coherent            |
| 8   | Rolling deploy               | Advance the hub pin mid-window                      | Intents carry `generation`; version ratchet: mismatched = STANDDOWN (18.2 R5); client re-reads sync_version, mutates nothing  | stale-generation intent refused                                   |

## 4. Decomposition and dependency-ordered acceptance

All in packages/suspenders; no new package, no new daemon:

1. `hooks/lib/reconnect-sync.ts` — the sync session (R1): pure, injected;
   exported face lands first.
2. Store migration: `reconnect_outbox` (R2) + `artifacts` (R4) tables +
   instanceId pinning generalized from consult_outbox_meta to a store-level
   row; `cursors` untouched (reused as-is).
3. Store faces: `GET /sync/manifest`, `POST /sync/drain`, `GET /sync/events`,
   `GET /sync/artifacts` — small, shape-validated, bounded (16 KB manifest,
   LIMIT-capped pages, readJson idiom).
4. fleet-loop tasks: `reconnect-sync` (client cadence + subscribe re-attach
   trigger) and `event-retention` (authority cadence, R3) — attempt-stamped,
   pause-flag honoring.
5. Offline intent minting: `work done --defer` (partitioned close → outbox
   row, never a silent failure), `coord message --defer` analog, and the
   `ack`/`decision` mint sites.
6. Board: canonical read + degradation banner ("last-known, stale Ns") +
   artifact/ancestry gap rows (Lit, tokens; createTextNode — never
   innerHTML).
7. Acceptance drills (§3 matrix) as `test/reconnect-sync.test.ts` fixtures;
   each lands with its row.

Dependency order: 1 → 2 → 3 (schema + faces), 4 → 5 (tasks + mint sites),
6 (UI), 7 (drills). Each step lands with its drill before the next.
Implementation items mint from this §4 only after review and only after the
sustained40 gate opens (same gate as 18.1/18.2).

## 5. Alternatives considered

- **Bidirectional sync / CRDT merge of the work graph**: rejected —
  adjudication.c71-73 ruled ONE WRITER PER PROJECT, epoch-fenced transfer,
  NO automatic CRDT; two done events for one claim is evidence corruption,
  not a merge.
- **Ship the store bytes (snapshot/file transfer, litestream-style)**:
  rejected — a second truth channel for the same rows; the store is the
  single writer and clients read bounded faces, never the db file (the
  never-raw-sqlite3 law); scrub/audit gates never see a db copy.
- **Replay from event id 0**: rejected — unbounded replay; keyset + horizon
  + snapshot recovery is the bounded alternative.
- **WS feed as the replay surface**: rejected — the feed is delivery, not
  durability; its line numbers are not event ids; replay reads the store
  via keyset faces only.
- **Client-side merge intents**: rejected — merge is authority-only; a
  client merge intent is the double-merge bug wearing a contract.
- **Unbounded events table (status quo)**: rejected — breaks replay bounds;
  the retention sweep keeps the stream bounded while rows keep truth.
