numbers canonical on /usage and show concise links from overview; verify no
metric disappears"). Evidence: every surface below was fetched over HTTP from

## Conclusions

1. **Nothing to remove on the live surfaces.** No page repeats a fleet
   overview or metrics summary; the single usage summary lives on /usage.
   Removing the belt per-endpoint tallies would delete metrics that /usage
   does not carry (usage_rollup token/request analytics vs metrics.db
   per-endpoint tallies) — rejected under "verify no metric disappears".
2. **Usage numbers are canonical on /usage** — verified, not just asserted.
3. **Concise links already exist**: the shared `fleetNav()` strip
   (`hooks/lib/theme.ts`) renders `Metrics → /usage` on every surface
   (board, consoles, belt.local, bar.local). No overview page exists live to
   link from; the nav is the fleet-wide concise link.
4. **Known overlap, deliberately left**: belt.local renders two recent-route
   logs (Routing log from `/api/status` `routing_tail`; the remotes log from
   `/api/metrics` `recent`). They draw from different sources and carry
   disjoint fields (`category/tier/escalated` vs `role/FAILED`); merging them
   would drop fields and is out of this item's scope.
