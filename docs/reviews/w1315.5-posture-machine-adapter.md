# W1315.5 — review of W1315.2 (6414ab85) posture machine adapter

Read-only review of commit `6414ab857ca3fa1bae2653699c1eae00d94076c6` against
`docs/superpowers/specs/2026-10-26-hub-postures-design.md`. No edits to
W1315.2; verification ran in a detached worktree at that exact commit.

## Evidence

All 48 posture specs pass at 6414ab85 (`playwright test` over
`packages/suspenders/hooks/lib/posture/*.e2e.ts`, ad-hoc config — see wiring
gap N3). Three targeted probes against the shipped exports confirmed the
findings below.

## Findings

B1 (blocking) — `writeStackPostureConfig` bypasses the migration backup.
`migrateStackPostureConfig` enforces the spec's "retain a recoverable
original" by writing `<stack>.pre-postures.bak.json` before the first embed,
and `saveStackPostureSelection` refuses an unmigrated file ("has not been
migrated"). `writeStackPostureConfig` has neither guard: on a stack file with
no `postures` key it embeds the document and leaves no backup. Probe on a
fresh `stack.json`: `backup exists: false | postures embedded: true`. Fix:
require `current.snapshot.document` (route first embeds through migration), or
write the same backup there.

N2 — absent machine config is an unqualified `ENOENT` naming the legacy twin.
`readStackPostureConfig` on a missing path throws
`ENOENT ... open '<dir>/stack.yaml'`, pointing at the legacy name the caller
never asked for; the spec asks for source-qualified diagnostics. The stack
API also has no create leg (`expectedRevision: string`, unlike
`writePostureConfig`'s `string | null`), so a machine with no conf cannot be
bootstrapped through these functions.

N3 — the new specs are not selected by any checked-in config.
`packages/suspenders/e2e/playwright.config.ts` has `testDir: "."` /
`testMatch: "*.spec.ts"`; nothing matches `hooks/lib/**/*.e2e.ts`. The
foundation plan already records this prerequisite (W1294.1). The proof exists
but does not run in CI — a release gate for W1315.3/.4.

N4 — writing through the legacy name leaves a stale twin. With only
`stack.yaml` present, an update creates `stack.json` and leaves `stack.yaml`
holding the pre-update bytes; `migrateYamlConf` then returns "kept" and never
renames the original to `.bak`, so two 0600 twins diverge permanently.

N5 — `postureFromLegacyInventory` accepts an empty `entries` array and emits a
posture with no references; "before/after effective-policy parity" is vacuous
there. Consider rejecting an empty inventory.

## Confirmed against the design

Stack embedding preserves topology and extension fields; the revision is a
hash of the whole machine file (full-file CAS) and invalidates on unrelated
edits; legacy names are read-only and only as JSON; the backup is byte-exact,
mode 0600, conflict-guarded and idempotent; explicit-inventory migration
round-trips placements, ceilings, OFF/0 and CAN replacement and rejects
missing hub/model/lanes and conflicting capacity; writes ride the existing
atomic 0600 `writeJsonConf` helper.

VERDICT: FAIL - writeStackPostureConfig embeds postures into an unmigrated machine file with no recoverable backup (B1); N2-N5 non-blocking.
