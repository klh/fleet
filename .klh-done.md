# W244 — knowledge queue: parser-change reprocess checkpoint

2026-10-11, lane autow244-p98b319584008df14. Branch `suspenders/W244`.

## What landed

- `hooks/lib/knowledge-ports.ts`: done queue rows carry `prompt_hash` — the
  sha256 of the distill prompt (the parser) that processed them, stamped at
  `complete()`, which also RETAINS the payload (the re-ingest source; it was
  cleared before). New port method `reprocessCheck(cur, apply)`: when the
  active prompt hash (`currentPromptHash()`) moves off the one-row
  `queue_checkpoint` table, done rows distilled under an older parser
  re-enqueue EXACTLY ONCE — one `BEGIN IMMEDIATE` tx marks the archive
  (`reprocessed_at`), copies the sources (`reprocess_of`), advances the
  checkpoint; the in-tx re-check kills the worker/CLI race. Payload-less
  legacy rows are marked-and-skipped; a reprocess copy that dies poisoned
  re-arms its parent in `fail()` — no orphans, no double-spend.
- `hooks/bin/knowledge-worker.ts`: the tick fires the checkpoint every pass
  (a live `knowledgeworker.md` edit applies to the next queued job AND
  requeues its older-parser work); `--once` runs the checkpoint pass before
  the empty-gate so a pure reprocess drains.
- `hooks/bin/coord.ts` + `hooks/coord/knowledge.ts`: new verb
  `coord knowledge-reprocess [--apply]` — dry-run default.
- `hooks/lib/govdb.ts`: guarded-ALTER heal + `queue_checkpoint` on open.
- `test/w244-reprocess.test.ts`: 7 tests (migration, stamp+retention,
  dry-run, exactly-once, poison re-arm, worker e2e, CLI).
