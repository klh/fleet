## Findings

1. **Cloud glm leg bounces on Responses params** — codex's Responses-API
   request carries `parallel_tool_calls` + `prompt_cache_key`; the litellm
   zai row refuses them (`UnsupportedParamsError`, no `drop_params`), so
   `--model glm-5.3-flash` fails while local tiers (`local-reason` :8903)
   pass. Fix is one of: `litellm_settings.drop_params: true` in the machine
   `litellm.yaml` (operator config), or a buckle-side param diet on
   openai-dialect egress (W914 territory). NEED_DECISION emitted 2026-10-19.
2. **`codex exec resume` takes no `-C/--cd`** — the spawn cwd anchors the
   session-cwd filter. Any future fork wiring must spawn from the lane
   worktree cwd, not pass -C.
3. **Starter-fork wiring for codex remains open** — `forkArgs` in
   `hooks/lib/executors/codex.ts` is still `null`; `exec resume <id>` /
   `exec fork <id>` verbs verified live, but `ensureStarter` seeds with claude
   grammar (`-p … --output-format json`), so wiring needs a per-harness seed
   recipe first (W454 module-header note stands). This item verifies the
   capability; wiring is a follow-up for the parent.

## Resume semantics verified live

  `CODEX_HOME/sessions/<y>/<m>/<d>/rollout-*.jsonl`; cwd-filtered by the
  spawn cwd; same CODEX_HOME required (ephemeral wraps that delete the home
  on child exit lose resume).

  semantic) — verified present in `--help`, not yet exercised e2e.
