Overwhelmed and disorganized by Codex and Claude Code?
Use Nimbalyst Wiki.
A local wiki your agents write for you
so you can think, organize, and set direction
Your agents organize decisions, open questions, and the big picture into a wiki you can edit.
Free plugin for Claude Code, Codex, Cowork, Cursor, VS Code or any MCP agent. No Nimbalyst app or account needed.
How it works
Plug it into your coding agents
Install it in your agent workspace
Pick the agent workspace you use. Each one takes one setup step, and every agent works on the same wiki, so you can switch later without losing anything.

Install the Nimbalyst Wiki plugin. It brings the wiki tools, the setup, capture and recall commands, and two reminders. At the start of a session the agent hears what your wiki covers and which pages cover the files you changed, and before a session ends it is reminded to record what you decided.
/plugin marketplace add nimbalyst/nimbalyst-wiki
/plugin install nimbalyst-wiki@nimbalyst-wiki
Then run /nimbalyst-wiki:setup and your agent builds a Home page, a writing guide and starter pages from your repo. For a short tour first, run /nimbalyst-wiki:start.
Install the Nimbalyst Wiki plugin in the Codex CLI. It brings the same wiki tools and setup, capture and recall skills as in Claude Code. Codex does not run the plugin&#39;s reminders, so ask it to record what you decided.
codex plugin marketplace add nimbalyst/nimbalyst-wiki
codex plugin add nimbalyst-wiki@nimbalyst-wiki
Then ask Codex to set up a wiki for this repo.
Install the nim CLI, then add the wiki server. The Codex app, the Codex CLI and the Codex IDE extension share the same settings, so one command adds the wiki to all of them.
npm install -g @nimbalyst/cli
codex mcp add nimbalyst-wiki -- nim mcp
Restart the Codex app, then ask it to set up a wiki for this repo.
Install the nim CLI, then add the wiki server to .cursor/mcp.json in your project.
npm install -g @nimbalyst/cli
{
"mcpServers": {
"nimbalyst-wiki": {
"command": "nim",
"args": ["mcp", "--workspace", "${workspaceFolder}"]
}
Then ask the agent to start a wiki for this repo.
Install the nim CLI, then add the wiki server to .vscode/mcp.json in your project and use it from Copilot in agent mode.
npm install -g @nimbalyst/cli
{
"servers": {
"nimbalyst-wiki": {
"command": "nim",
"args": ["mcp", "--workspace", "${workspaceFolder}"]
}
Then ask the agent to start a wiki for this repo.
Install the nim CLI, then add the wiki server to the Claude desktop app&#39;s MCP config, pointed at the folder that holds your wiki.
npm install -g @nimbalyst/cli
{
"mcpServers": {
"nimbalyst-wiki": {
"command": "nim",
"args": ["mcp", "--workspace", "/path/to/your/project"]
}
If the app cannot find nim, use the full path that `which nim` prints.
nim mcp is a standard MCP server on stdio. Point any MCP client at it.
npm install -g @nimbalyst/cli
nim mcp
The tools are the same in every agent, so a wiki started in one is ready in the others.
Run setup and your agent builds the wiki
Claude asks who the wiki is for, then writes a Home page, a writing guide and starter pages from your README and docs, as markdown files in your repo.
/nimbalyst-wiki:setup
Capture what you decided
At the end of a session, capture writes each decision into the page it affects, with who decided, when and what was passed over, and records open questions with their owners.
/nimbalyst-wiki:capture
Read and edit it in your browser
Ask your agent to open the wiki in your browser, with nothing to install, or run nim wiki serve from a terminal. Edit pages, drawings, mind maps, spreadsheets and mockups, with edits saved straight to the files and what your agent writes showing up live.
npm install -g @nimbalyst/wiki-web
nim wiki serve
See what is decided and what is still open
Every decision and open question is marked in the page it affects, and an index page links to each one, so you can catch up in a few minutes.
Track things with types
Ask your agent to track competitors, customers or features, and it creates a type with the fields you care about. Each item gets its own page with those fields at the top, and the type keeps a table of every item.
Track our competitors in the wiki: category, threat, setup speed and payment recovery for each.
Add drawings, mind maps, spreadsheets and more
Pages hold more than text. Ask your agent for an interactive HTML page, a drawing, a mind map, a spreadsheet, a data model, a mockup or a canvas, and it builds the page in your wiki. Open any of them in your browser to edit, or start one yourself from the New page menu.

Share it with your team
When your team needs the wiki too, run /nimbalyst-wiki:team in Claude Code, or ask any agent to move it to Wiki Teams. Your text pages, typed pages and the links between them move to a team wiki where everyone edits the same pages in their browser and every teammate&#39;s agents write into it.
The team command installs the nimbalyst-wiki-team add-on after you agree.
Sign in with your Google account.
Create a team and invite teammates by email.
The team wiki runs on Nimbalyst&#39;s servers on Cloudflare, at console.nimbalyst.com.
In Cursor, VS Code, Cowork and other agents, sign in with nim login and your agent uses the team wiki through nim wiki commands.

The wiki in Claude Code and your browser
What you get
Plain files, on your machine, for every agent
Files in your repo
Text pages are markdown files in your project. By default the wiki lives in nimbalyst-local/wiki, a folder kept out of git so it stays private to you. To share it through your repo, put it in a checked-in folder like docs/wiki and diff and commit it like code.
Stays on your machine
A local wiki needs no account and no server. The browser view listens on your machine only and is protected by a token.
One wiki across every agent
Claude Code, Codex, Cowork, Cursor and VS Code all use the same tools on the same files, so you can switch agents without losing what they wrote.
Drawings, sheets and mockups too
Drawings, mind maps, spreadsheets, data models, mockups and canvases are pages too. Each keeps its editor&#39;s own file, such as .excalidraw, .csv, .prisma or .mockup.html, so other tools can still open it.
Open source
Open source and MIT licensed
The Nimbalyst Wiki plugin, the nim CLI, its MCP server and the browser app are MIT licensed. The plugin&#39;s code is on GitHub, where you can read it, file issues and send pull requests.

Questions
Common questions
Why keep a wiki when you work with coding agents?
A few agent sessions a day produce more decisions and open questions than one person can track, and they end up buried in transcripts. The wiki gives you a short, current record of what was decided and what is still open, written by your agents for you. More on
why working with coding agents gets overwhelming
.
What should go in it?
Decisions and their reasons, open questions, the preferences and constraints people set, and hard-won lessons. The work itself stays in your sessions, code and trackers, and the wiki links to it. See
architecture decision records your coding agent writes
for how each decision is recorded.
Where does my wiki live?
In your project, in nimbalyst-local/wiki by default, which git ignores. Choose a folder such as docs/wiki to check it in and share it through git.
How does my agent use what the wiki already says?
Pages can name the code they cover. In Claude Code, the plugin tells the agent at the start of each session what your wiki covers and which pages cover the files you have changed, and capture starts from the pages your changes touched. Run /nimbalyst-wiki:recall, or just ask "why did we...", and the agent answers from what the wiki says and decided. It can also check the wiki for broken links and stale or orphaned pages. The docs explain
how capture records decisions
and
how recall answers from the wiki
.
Is it the same as Claude Code memory?
No. CLAUDE.md and AGENTS.md hold instructions you write for the agent, and Claude Code's auto memory holds notes the agent writes for its own next session. The wiki holds pages written for you, with what was decided, what is still open and what you are tracking. We compare them in
Claude Code memory vs a wiki your agents write
.
How is it different from Obsidian, Notion AI or Basic Memory?
Your coding agent writes the wiki as part of each session, with each decision marked with who decided, when and what was passed over, as markdown in your repo with no account. Obsidian gives you a vault and conventions you design yourself, Notion AI works inside a hosted workspace, and Basic Memory builds a notes graph for your AI across conversations. ,

Do I need an account?
Not for a local wiki. You only sign in to Nimbalyst when you share the wiki with your team.
Do I need the Nimbalyst app?
No. Your agent, the nim CLI and the
browser view
give you a complete wiki, including drawings, mind maps, spreadsheets, data models, mockups and canvases you can edit in the browser. Open it in the Nimbalyst app when you want the wiki in the same place as your sessions and code.
What is Nimbalyst?
Nimbalyst makes a wiki your coding agents write for you, and a visual workspace for working with Claude Code, Codex and other agents. The wiki works in your coding agent with no app or account. The desktop app runs your agents in parallel sessions with visual editors for tasks, docs, diagrams, mockups, spreadsheets and code, and every AI edit arrives as a diff you can review. Both are free and open source for individuals, on macOS, Windows and Linux, and Wiki Teams makes the wiki multiplayer.
Is it the same wiki as the one in the app?
Yes. The app's Local wiki is the same folder of files, so you can start in your agent and open the app later without moving anything.
